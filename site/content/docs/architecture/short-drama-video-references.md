# 短剧镜头视频参考与采用

2026-09-10，工作树待提交批次。部署证据见 PROJECT_MEMORY.md 最新续记。

分镜编辑页确认剧本、资产与对白；分镜工作室准备视觉参考和参数并执行生成。帧图不是必经的三道工序：按型号可使用纯文本、首帧、首尾帧或主体图片路径，关键帧只在支持的接口出现。first/key/last 是语义槽位，不是任意参考文件列表。

工作室主体图片协议按精确型号核验开放：HappyHorse 1.1 R2V（图片总数9，3–15秒）及 Vidu Q2/Q1/2.0。前后端分别校验总数、组数和组内图片限制；工作室支持同一角色的多角度组内选择/补图与排序。HappyHorse共9张（平铺图号，同名表示相同主体）；已核验Vidu每组最多3张、总体最多7张，并保留原生具名组。HappyHorse 按 Image N 映射，Vidu 按 @名称映射，均使用实际媒体顺序。来源可从已有文件库选择，缩略图可放大；不自动选入所有资产图。已有首尾帧模式仍传首帧和尾帧两张图片。

本次视频模型首先回填系统共享默认配置（当前项目设置入口也使用此配置），可手动覆盖，清空恢复默认；分辨率、时长/比例约束跟随实际选型。未核验协议不借相似名称开放，未配置模型不会自动创建或切换套餐端点。Vidu 分辨率投影到原生请求 resolution 字段。未知计价保持未知，不套用别的模式价格。

主体参考浏览器草稿按 shot_id 保存，属于当前浏览器便捷恢复；已提交任务的 VideoMediaInput.subjects、具名帧、模型 revision、执行提示词均冻结。预览由同一厂商 profile 编译，ReviewGenerationContext 包含主体名称、媒体顺序与参数。旧无主体报告按空主体处理；图片顺序或用途变化导致版本不一致。视觉预检只涵盖实际勾选发送的图片（目前上限4张），应用优化不是质量通过。

准备度使用与提示词上下文共用的模式表，并检查当前型号时长。它与 shot.status 信息确认、runtime 任务状态分离。主体计数检查是准备度提示，提交仍需经过文件解析及完整模型契约校验。

历史视频点击仅预览。采用接口仅允许当前镜头成功任务关联或受控 artifact 文件，通过当前 file_id 比较和行锁更新 generated_video_file_id/version，并维护文件使用关系。后续成片时间线读取此字段，已经导出的文件不改变。普通视频生成保留既有 CAS 自动采用行为，因此新任务完成后必须核对当前版本；标记“当前用于成片”不代表人工质量审核通过。

无新增数据库迁移。任务中心仍保持通用状态，提示词、参考图与预检详情留在工作室。


2026-09-11：人物角度目录由本镜头ShotCharacterLink→CharacterImage及可选ActorImage读取当前有效槽位文件。角色定妆与演员基准分别标注来源；首/关键/尾帧选择各自保存，不会因目录新增图片自动全选。视频页与最终发送预览均展示所有角度，组内ordinal、组间顺序与实际调用保持一致；准备度采用图片总数。主体草稿仍限当前浏览器，并非服务器角色分组关系。改组名后通过已选人物图片识别原组，避免补角度另建同角色组。


## 生成设置同步（2026-09-11）

工作室使用按shot_id隔离的ShotDetailDraftStore。各标签共用即时草稿，PATCH逐镜头串行，确认只合并已提交且未再次修改的字段；失败保留待保存状态和重试入口。标题/剧本备注同样串行并仅更新对应字段。准备度在保存成功后重查，不使用保存前GET取得的旧时长结论。

进入视频tab和生成前先等待详情与维护文本保存，然后读取最新详情、帧槽位、镜头元数据、项目默认画幅与共享默认模型。同步应用状态后才按最新渲染构建预览。输入来源、已采用帧、模型及规格参与预览新鲜度；费用确认后再次核对，变化不提交。历史预检仍保留原快照，不能因新设置同步就认作适用于当前版本。

刷新同一模型修订时保留仍有效的本次分辨率和音频选择；换型号/修订后按新规格初始化。只更新前端保存编排与显示，后端契约、默认模型值和数据库结构不变。
