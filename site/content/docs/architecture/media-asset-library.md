# 富媒体素材库与生成引用

## 文件生命周期

所有上传先创建全局 `FileItem`，元数据保存在 MySQL，原始对象写入 RustFS 的 `files/{object_id}/{filename}`。资产关联由 `AssetFileLink` 单独保存，因此“仅上传”不是临时状态：文件会出现在全局文件管理，也可在任一资产详情通过“从文件管理选择”搜索、分类、分页预览后再关联。

解除资产关联不会删除 `FileItem` 或 RustFS 对象。删除全局文件时，如果仍存在资产附件或音频资产引用，服务返回 `409`；解除业务引用后才允许删除原始对象。视频兼容预览对象位于 `previews/{file_id}/browser.mp4`，删除原文件时同时清理该派生对象。

## 预览

- 图片缩略图使用 `object-contain` 保持完整画面，并支持大图弹窗。
- 视频和音频预览端点支持单段 HTTP Range，返回 `206`、`Accept-Ranges` 和 `Content-Range`。
- 浏览器不兼容的视频在首次预览时由 FFmpeg 转为 H.264/AAC MP4 并缓存，原始下载不变。
- TXT、Markdown 和 DOCX 返回安全的纯文本只读预览；PDF 保持浏览器内联预览。DOCX 只提取正文，不承诺还原复杂排版。

## 生成引用

关联始终是可选增强，不是生成前置条件。`enabled=false` 的附件不会进入生成上下文。

- 资产图片：启用的图片按主参考和排序进入参考图候选；素材说明与 TXT/Markdown/PDF/DOCX 正文作为有长度上限的软提示词追加。
- 分镜视频：门禁根据镜头关联的角色、演员、服装、场景和道具汇总附件。只有所选模型能力表声明支持时，图片、视频和参考音频才转换为具名主体媒体。
- 用户在生成界面显式选择的媒体优先；自动素材不会覆盖显式主体，也不会把供应商不支持的字段发送到 API。
- 音频只有在模型支持参考音色、并能与同一主体图片或视频绑定时才作为生成输入；镜头后期配音、音乐和音效继续走独立音轨合成链路。

## 当前边界

文件库目前是本地部署实例级资源，尚无多用户/项目级权限隔离。PDF 扫描件不执行 OCR；无法提取文字层时不会臆测正文。音视频时长、分辨率和编码元数据的上传后自动回填仍属于后续增强。
