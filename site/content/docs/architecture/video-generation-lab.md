# 视频生成实验室

视频生成实验室独立于项目、资产和分镜生产流程，用于验证已登记的视频模型、`video_prompt` 提示词模板、关键帧与主体参考对生成结果的影响。

## 页面与输入结构

页面复用实验室的共享布局、输入区和历史组件。历史由用户提示词消息和视频任务消息组成；任务消息展示状态、进度、失败原因及成功后的内嵌视频预览。

关键帧按具名槽位保存，而不是无类型图片列表：

- 首帧：`frames.first`
- 尾帧：`frames.last`
- 关键帧：`frames.keys`

三个槽位均引用资料库文件：每个引用包含 `file_id`、`media_kind: image` 和组内 `ordinal`。主体参考独立保存为 `subjects`；每个主体有名称以及一组按顺序排列的图片、视频和可选参考音频 `file_id`，提示词可以用 `@主体名称` 指代它。帧槽位只能引用图片，主体名称在一次提交中必须唯一；参考音频必须绑定同主体的图片或视频，不能单独提交。

API 和任务快照只保存资料库文件标识，不保存供应商侧媒体表示。统一生成门禁负责验证文件类别和模型能力，Worker 仅在执行期通过文件解析器取得供应商所需媒体表示。

## 能力约束

模型能力接口 `GET /api/v1/llm/video-generation-options` 描述文生、首帧、尾帧、关键帧、主体图片/视频、可选时长和组合上限。前端按模型动态隐藏不支持的帧入口、提供合法时长，并在提交前检查必需素材；后端会再次执行同一能力校验。

Vidu 主体参考映射到 `reference2video`。支持实体的模型使用 `subjects`；`viduq3-mix`、`viduq3-drama`、`viduq3-ad` 使用顶层参考图片，并拒绝参考视频。`viduq2-pro` 可使用主体视频。主体参考和帧参考默认不能混用。

阿里百炼按模型家族组包：HappyHorse t2v 不发送素材，i2v 要求且只发送首帧，r2v 要求参考图片或视频；r2v 与 Wan 2.7 可把同主体的一条音频映射为视觉素材的 `reference_voice`。Wan 3.0/2.7 使用 `media`，Wan 2.6 使用旧版 `reference_urls`、`size` 与显式 `audio`。关联素材始终是用户可选行为，但选择后必须符合所选模型的真实能力；不支持参考素材的模型仍可走纯文本生成。

OpenAI 视频当前只接受 `sora-2` / `sora-2-pro`、4/8/12 秒、横屏或竖屏尺寸和单首帧参考，不再发送供应商未声明的 `ratio`、`seed`、`watermark`。火山 Seedance 1.5、Vidu Q1/Q2/Q3 与可灵 3.0 也分别使用模型级时长、比例和素材边界。

## 统一任务提交与结果

视频实验室通过固定入口提交异步任务：

`POST /api/v1/studio/generation-tasks/labs/video/sessions/{session_id}/tasks`

路径绑定视频模态和 `video_generation` operation。请求体提供已登记的 `model_id`、最终 `execution_prompt`、`ratio`、可选帧槽位和主体参考；服务端校验会话属于视频实验室，且不允许由请求体切换 operation 或媒体结构。

用户消息、携带 `task_id` 的任务消息和统一 `video_generation` 任务在同一事务中创建，提交成功后才投递 Worker。任务目标类型为 `experiment_session`，不会读取或回写任何 `Shot`。任务快照冻结模型修订、提示词、文件 `file_id` 和目标会话，但不保存凭据值。

前端通过 `GET /api/v1/film/tasks/{task_id}/result` 轮询任务。Worker 将成功、失败或取消状态及结果快照写回同一条任务消息；成功视频由统一产物流程归档到资料库，页面使用结果中的资料库文件信息播放并在刷新后恢复历史输入和预览。

## 与分镜视频生成的边界

- 视频实验室：独立验证模型、提示词、关键帧和主体参考，不绑定镜头，不更新分镜状态。
- 分镜工作室：生成前需要镜头、时长、准备度和项目上下文，成功后会发布并回写镜头的生成视频。
