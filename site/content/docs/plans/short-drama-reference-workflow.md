# PL-016 短剧创作与多参考视频闭环

2026-09-10，工作树待提交批次。状态：P0–P4 本批代码、离线验证与部署完成；真实出片验收待用户显式生成；不代表真实生成质量已验收。保留 PL-001 至 PL-015 的所有未关闭工作。

## 目标与判断

剧本 → 分镜准备确认 → 角色/场景/道具视觉资产 → 镜头参考策略与提示词 → 可选预检/智能调整 → 视频候选 → 明确采用 → 成片拼接与音字幕验收。质量关注身份、服装、空间、动作节拍、镜头衔接和叙事；费用是提交约束之一。

首尾帧控制起止画面；主体多图维持人物、道具或场景特征。多图不是越多越好，错误身份、不同服装和冲突场景会降低稳定性。先选适合镜头的生成策略，再核对精确模型/端点能力。不把角色、场景资产全部默认选中，不把普通关键帧误称为任意多图参考。

## 本批执行顺序及完成门槛

1. P0：核对全链路和已注册供应商/实际配置，建立官网证据与缺口。已发现工作室 subjects 固定为空、选项只根据已有帧而不根据模型、HappyHorse R2V 能力登记错误；现有导出按章节/镜头顺序使用 generated_video_file_id。
2. P1：开放模型感知的主体图片参考选择、用途命名、预览、移除和顺序；保留明确的首帧/首尾帧路径。当前已配置的 Seedance 1.5、HappyHorse I2V 不自动替换为 R2V。修正已核验 HappyHorse R2V 的输入和总数约束；未经核验的多图协议不开放。
3. P2：所选图片、用途、顺序贯通发送预览、预检版本、模型请求和任务快照；变更参考后旧预检不能被标记为同版本。不得静默丢图或自动收费重试。
4. P3：检查采用视频与成片引用关系，补充明确操作和版本提示；将尚未实现的多轨/裁剪/逐角色音色列为后续，而不把简单拼接冒充完整专业剪辑。
5. P4：后端契约/载荷/关联回归、OpenAPI、前端类型与构建、无付费浏览器流程、应用部署健康检查，逐项记录证据；真实供应商视觉质量由用户显式生成验收，不以测试替代。
