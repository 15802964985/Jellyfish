### 关键实现与兼容边界

- 新增 `GenerationOperation.video_edit/quality_preflight`，编辑模型与普通视频生成分离，模型管理不允许设成普通视频默认值，实验室普通生成筛选排除编辑专用型号。
- `GenerationSubmitRequest` 新增可空来源指纹和预检人工重试编号；新增编辑 media/operation 输入，旧 image/video/text 输入仍兼容。任务、来源、预算、媒体版本和外部任务凭证使用现有 JSON/关联表，无新增表或列，本批不需要数据库迁移。
- `quality_source_fingerprint` 只比较来源身份和内容，忽略查询顺序及提示词逐字包含标记；预览后来源变化返回 409，要求重新预览。精确摘录未定位只提示未知，不靠括号/关键词硬判语义冲突。
- 最终提示词按已核验精确型号检查；超限返回 422，不让供应商静默截断。HappyHorse 中英文混合采用保守阈值，明确记录。未知型号记录 unknown，后续扩展预算注册，不虚构统一 token 上限。
- 智能预检以模型返回的可读文本呈现事实/推断/风险/建议，不要求每家模型强行返回同一种 JSON。图文模式仅在实际附带图片时记录 images_analyzed，visual_verified 始终不是“无穿帮保证”。图片只在 Worker 内存中转 data URI，不存进任务 JSON。
- 编辑请求以用户请求编号幂等；同编号不同内容拒绝；提交结果不明不自动再次收费请求。取消为尽力取消，不能承诺供应商停止计费。服务崩溃后的未知请求需要人工核对凭证，不能直接循环重试。
- 编辑成功只归档新版本，不自动覆盖镜头或时间线。采用接口验证镜头归属及当前文件 CAS，原视频仍在文件库。关闭窗口后可从编辑历史重新读取任务和结果。
- Runway 无 keep_audio 字段：选择保留音轨时本地重新合成，并校验源/结果时长；先保留已付费的原始输出，后处理失败可下载检查，不因后处理失败自动重新生成。

- 生成结果不自动覆盖原片或时间线；保留源文件、修改指令、模型/规则版本和采用关系。任务创建幂等、失败可诊断，未知提交结果不重复收费重试。

## P3：验收与推广

- 离线协议、能力筛选、版本不覆盖、跨镜头隔离、取消/超时、媒体归档和费用确认测试；同步 OpenAPI、生成客户端、手册与台账。

## 调研依据与使用边界

- [MovieAgent](https://github.com/showlab/MovieAgent)：借鉴分层镜头规划与角色资料约束，不整套安装其 GPU 管线或复制未审计语料；本次页面显示 357 stars，不能据此断言用户满意度。
- [VBench](https://github.com/Vchitect/VBench)：借鉴分维度评估方法，页面约 1.8k stars；是评估项目，不是能保证质量的提示词插件，首期不部署权重。
- [Runway 提示词介绍](https://help.runwayml.com/hc/en-us/articles/47313698911891-Introduction-to-Prompting)：参考精确描述与迭代原则，按具体型号编译，不堆叠冗长通用负面词。

- [Runway 模型 API 说明](https://docs.dev.runwayml.com/guides/models/)：Aleph 编辑候选；本系统尚无该适配器，不列为可直接使用。
