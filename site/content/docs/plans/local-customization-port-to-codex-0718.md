# 本地二开迁移至 codex/0718

## 目标

以 `upstream/codex/0718` 为新底座，迁移 `local/stable-2026-09-02-media-assets` 的全部业务能力；当前 `E:\Jellyfish` 稳定部署在验证完成前保持不变。

## 迁移范围

1. 本地安全部署：E 盘 Docker、仅本机端口、MySQL、Redis、RustFS 与 FFmpeg。
2. 数据即时刷新：项目、章节、资产、提示词和模型管理的新增、修改、删除后刷新。
3. 列表治理：非系统数据删除、章节与任务分页、弹窗高度和筛选交互。
4. 任务中心：持久任务查询、默认进行中、终态查询、低频轮询及重复展开稳定性。
5. 模型管理：默认模型设置、真实连接测试、密钥更新、阿里百炼和火山引擎多模态能力。
6. 剧本导入：TXT、Markdown、PDF、DOCX 上传、解析和智能拆解入口。
7. 富媒体资产：图片、视频、音频、文档上传及演员、角色、场景、道具、服装附件。
8. 智能可选引用：启用、主参考、排序、逐项移除、全部不使用及无素材回退。
9. 配音音效：音频素材库、镜头音轨、FFmpeg 非阻塞后期合成。
10. 中文配置使用手册与架构文档。

## 架构适配原则

- 保留 `codex/0718` 的统一 generation contracts、submission、runtime、publishers 与 artifacts。
- 不恢复上游已删除的旧图片任务和旧提示词链路。
- 本地生成能力接入统一模型目录与统一任务提交接口。
- 本地 SQL 迁移转换为 Alembic revision，并验证已有数据库 reconciliation。
- OpenAPI 以合并后的后端为唯一真值重新生成，不手工合并 generated client。
- 任务中心保持通用轻量，业务上下文继续留在对应工作台。

## 验收门槛

- 现有稳定环境和数据全程不受影响。
- Alembic 能从当前数据库状态安全升级，原有记录数量不减少。
- 无素材、无音轨时维持上游默认生成流程。
- 关联素材与音轨均为可选增强，失败时不阻断已成功生成结果。
- 所有新增 API 使用 generated client；后端相关测试、前端类型检查和生产构建通过。
- 核心页面刷新、删除、分页、模型调用、任务查询、素材与生成链路完成烟雾验证。

## 已知高风险点

- 上游删除旧图片任务接口，本地图片与视频适配需要迁移到统一生成链路。
- 上游引入 Alembic，本地 `009-add-media-asset-support.sql` 不能直接沿用为最终迁移方案。
- 上游重构模型目录和供应商能力，本地阿里百炼适配需重新落位。
- OpenAPI 与 generated client 变化很大，必须后端稳定后整体再生。
